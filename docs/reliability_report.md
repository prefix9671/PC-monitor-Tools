# 시스템 신뢰성 및 검사 효율 분석 보고서 (Reliability Report)

## 1. 개요 (Executive Summary)
본 보고서는 AOI(Automated Optical Inspection) 장비의 고정밀 검사 환경에서 본 모니터링 시스템이 장비 소프트웨어의 성능과 신뢰성에 미치는 영향을 분석합니다. 경영진(C-Level) 및 QA 팀은 본 도구를 통해 검사 속도(Cycle Time) 손실 없이 시스템의 잠재적 리스크(Disk I/O 병목, DB 부하 등)를 객착하고 대응할 수 있습니다.

## 2. 모니터링 아키텍처 및 안전성 (Architecture & Stability)
본 시스템은 장비의 실시간 검사 로직과 완전히 분리된 **비침습적(Non-invasive) 방식**을 채택하고 있습니다.

- **윈도우 표준 성능 카운터 (Logman)**: OS 수준에서 커널 데이터에 직접 접근하므로, 애플리케이션 레벨의 CPU 점유율이 1% 미만으로 극히 낮습니다. (5초 주기 설정 시 영향도 무시 가능)
- **PowerShell 기반 프로세스 추적**: 30초의 긴 주기로 동작하여, 검사 소프트웨어의 프로세스 컨텍스트 스위칭에 미치는 영향을 최소화합니다.
- **데이터 저장소**: 수집된 로그는 비동기적으로 기록되며, 검사 알고리즘의 메모리 영역을 침범하지 않습니다.

## 3. 핵심 시스템 영향 분석 (Impact Analysis)

### 3.1 검사 속도 (Cycle Time) 보존
AOI 검사는 고해상도 이미지 처리와 정밀 제어가 핵심입니다. 본 도구는 다음 방식으로 검사 속도를 보호합니다.
- **CPU 선점 방지**: 모니터링 프로세스는 낮은 우선순위로 동작하도록 설계되었습니다.
- **Interrupt 관리**: 네트워크 기반 모니터링 대신 로컬 로그 방식을 우선하여 네트워크 지연에 따른 사이드 이펙트를 차단합니다.

### 3.2 로컬 DB 엔진 및 기타 프로그램 모니터링
AOI 시스템에서 MSSQL/PostgreSQL 등 로컬 DB의 성능 저하는 검사 결과 기록 지연으로 이어집니다.
- **Disk I/O 추적**: DB 엔진의 `Write Bytes/sec`와 `Disk Queue Length`를 모니터링하여, DB 저장 지연이 검사 속도에 미치는 상관관계를 QA가 즉시 파악할 수 있습니다.
- **자원 경합 탐색**: 타사 백신이나 기타 백그라운드 프로그램이 CPU 피크를 유발할 때, 해당 시점에 AOI 검사가 지연되었는지 타임라인을 통해 교차 검증할 수 있습니다.

## 4. QA 운영 전략 (Operational Strategy)
QA 팀은 본 도구를 통해 다음과 같은 OS 레벨의 이슈를 진단합니다.

1.  **메모리 릭(Memory Leak) 조기 발견**: 검사 소프트웨어의 메모리 점유율이 시간에 따라 우상향 하는지 감시하여 장기 가동 시의 장비 다운타임을 예방합니다.
2.  **디스크 노후화 진단**: 특정 일시부터 `Disk Read/Write` 속도가 저하되거나 큐 길이가 늘어나는 경우, 장비의 SSD/HDD 교체 시기를 객관적 수치로 제안합니다.
3.  **검사 속도 상관관계 분석**: 제품 검사 시간이 평소보다 길어진 경우, 해당 구간의 CPU 피크 여부를 확인하여 코드 최적화 필요성을 판단합니다.

## 5. 결론 (Conclusion)
본 모니터링 시스템은 AOI 장비의 고유 기능을 저해하지 않으면서도, 시스템의 투명성을 극대화합니다. 이는 장비의 가성비(Uptime)를 높이고, 현장에서 발생하는 원인 불명의 검사 지연 이슈를 데이터 기반(Data-driven)으로 해결하는 강력한 QA 기반이 됩니다.
