# 파이썬 psutil 수집기 마이그레이션 (2026-03-24 업데이트 로그)

시스템 리소스 모니터링 도구가 기존의 PowerShell/Logman 하이브리드 방식에서 `psutil`을 활용한 **순수 파이썬(Python) 기반 수집기**로 전면 개편되었습니다. 이를 통해 데이터 수집 과정이 획기적으로 단순해졌으며, 비동기 병합 문제를 해결하고 대시보드에서 더욱 안정적으로 데이터를 표시할 수 있게 되었습니다.

## 주요 변경 사항

### 1. 신규 파이썬 수집기 아키텍처
- **`collectors/sampler.py`**: CPU 사용량, 메모리 상태, 드라이브별 디스크 속도, 프로세스별 자원 점유율을 1초 간격으로 추출하는 하드웨어 샘플러 구현. **시작 시 Windows 파티션 정보를 조회하여 `PhysicalDriveX`를 실제 드라이브 문자(`C:`, `D:` 등)로 자동 매핑**.
- **`collectors/aggregator.py`**: 데이터의 노이즈를 줄이고 중요한 스파이크를 보존하기 위해, 5초(Window) 단위 롤링 평균 및 최대값(Peak IO, Avg Mem, Peak CPU 등)을 계산하는 집계 로직 구현.
- **`collectors/writers.py`**: 표준화된 헤더를 적용하여 날짜별로 롤링되는 `resource_YYYYMMDD.csv` 및 `process_YYYYMMDD.csv` 출력 시스템 구축.
- **`collectors/core.py` & `cli.py`**: 기존의 단일 메인 루프를 분리하여, 핵심 로직을 담당하는 `MonitorEngine` 모듈과 터미널 제어를 담당하는 `cli.py` 도구로 TDD 기반 리팩터링을 완료했습니다.

### 2. Streamlit 대시보드 및 데이터 파이프라인 통합
- **`data_loader.py`**: 기존의 `pd.merge_asof` 로직을 완전히 제거했습니다. 대시보드는 이제 컬럼명을 분석해 자동으로 `resource`와 `process` 데이터를 식별하며, 정확히 일치하는 `Timestamp`를 기준으로 병합(`pd.merge`)을 수행합니다.
- **`app.py`**: 새로운 파이썬 수집 메커니즘이 자체적인 수집/집계 주기를 통제하므로, 대시보드에서 수집 주기를 동적으로 설정하던 레거시 UI 컨트롤을 제거했습니다. **날짜 기반 로그 선택 UI로 변경하여, 오늘 기준 최근 1주일 이내 로그를 자동 선택/로드**하도록 사용성을 개선했습니다.
- **`dashboards/*.py`**: 모든 차트가 명시적인 5초 Peak/Avg 파생 컬럼(`CPU_Avg(%)`, `Mem_Usage_Avg(%)` 등)을 바라보도록 맵핑했습니다. `storage.py`는 드라이브명으로 `PhysicalDriveX` 및 `C:` 형식 모두를 인식하도록 정규식을 확장했습니다.

### 3. 실행 래퍼 및 문서 업데이트
- **`start_monitor.bat` & `Monitor.ps1`**: 기존의 Logman 의존성을 제거하고, 단순히 관리자 권한 여부를 체크한 뒤 `.\venv\Scripts\python cli.py start`를 실행하도록 경량화 래퍼로 축소했습니다.
- **문서화(`docs/`)**: `project_structure.md`, `user_manual.md`, `optimization_proposal.md` 파일에 걸쳐 파이썬 수집기에 대한 내용을 업데이트하고, 제거된 기능과 신규 아키텍처의 의도를 명확히 반영했습니다.

## 추가 개선 (메모리 누수 조치)
- **Pyrefly 파이썬 언어 분석기 안정화**: 프로젝트를 불러올 때 Pyrefly가 수천 줄의 CSV 로그 데이터(`C:\SystemLogs`)를 스캔하며 메모리를 2GB 이상 점유하던 현상을 해결하기 위해, `pyrightconfig.json`을 추가하여 로그 및 데이터 폴더를 분석 대상에서 완전 배제했습니다.

## 테스트 및 검증 결과
- **CLI 도구 TDD 테스트**: `pytest`(unittest) 기반의 환경에서 파일 시스템 모의(Mocking)를 거치지 않고, 임시 디렉토리를 통해 `cli.py`가 실제 CSV 파일을 올바른 스키마로 생성하는지 검증을 완료했습니다.

## 구동 테스트 방법
1. **관리자 권한**으로 실행된 터미널(또는 CMD)을 준비합니다.
2. 백그라운드에서 실행 중이던 파이썬 수집기가 있다면 종료합니다.
3. 수집기 실행: `.\start_monitor.bat` (새로운 관리자 셸 창이 뜨며 `C:\SystemLogs` 폴더에 데이터를 기록하기 시작합니다.)
4. 대시보드 실행: `.\venv\Scripts\python -m streamlit run app.py`
5. 대시보드에서 동일한 타임스탬프로 기록되는 CPU/데이터의 Peak 범위와 Average가 한 줄의 데이터로 안전하게 추적되는 것을 확인합니다.
