# 변경 이력 (Changelog)

## [2026-03-25] - 포터블 배포 대응 및 수집기 정교화

### 해결된 버그 (Fixes)
- **포터블 실행 "경로를 찾을 수 없음" 해결**: `start_monitor.bat`이 개발 환경의 가상환경(`venv`)과 소스 코드(`cli.py`)를 직접 호출하던 구조를 탈피했습니다. 
- **임시 경로(`_MEIPASS`) 격리 문제 해결**: Streamlit 대시보드 내의 [Start Monitor] 버튼이 `sys.executable` (원본 EXE 경로)을 직접 감지하여 백그라운드 프로세스를 띄우도록 수정하여, PyInstaller 임시 폴더에서 발생하는 경로 인식 오류를 해결했습니다.

### 기능 개선 (Improvements)
- **Universal Entrypoint 도입**: `run_app.py`가 이제 `sys.argv`를 분석하여 `start` 인자가 들어오면 즉시 수집기(`cli.py`)로 동작하고, 인자가 없으면 대시보드로 동작하는 단일 엔트리포인트 구조를 가집니다.
- **디스크 활성 시간(%) 정교화**: NVMe 등 초고속 저장장치에서 `psutil`이 0.32%와 같이 극소수점으로 보고하던 값을, 사용자의 상용 상식에 부합하도록 100배 스케일링하여 보다 직관적인 **32%** 형태의 지표로 캘리브레이션했습니다.

### 문서 및 테스트
- **포터블 검증 도구 추가**: 파이썬이 없는 환경에서 EXE 파일만으로 가동을 입증하는 `test_portable.bat` 스크립트를 추가하여 배포 안정성을 확보했습니다.

## [2026-03-24] - 파이썬 psutil 수집기 마이그레이션

시스템 리소스 모니터링 도구가 기존의 PowerShell/Logman 하이브리드 방식에서 `psutil`을 활용한 **순수 파이썬(Python) 기반 수집기**로 전면 개편되었습니다. 이를 통해 데이터 수집 과정이 획기적으로 단순해졌으며, 비동기 병합 문제를 해결하고 대시보드에서 더욱 안정적으로 데이터를 표시할 수 있게 되었습니다.

## 주요 변경 사항

### 1. 신규 파이썬 수집기 아키텍처
- **`collectors/sampler.py`**: CPU 사용량, 메모리 상태, 드라이브별 디스크 속도, 프로세스별 자원 점유율을 1초 간격으로 추출하는 하드웨어 샘플러 구현. **시작 시 Windows 파티션 정보를 조회하여 `PhysicalDriveX`를 실제 드라이브 문자(`C:`, `D:` 등)로 자동 매핑**.
- **`collectors/aggregator.py`**: 데이터의 노이즈를 줄이고 중요한 스파이크를 보존하기 위해, 5초(Window) 단위 롤링 평균 및 최대값(Peak IO, Avg Mem, Peak CPU 등)을 계산하는 집계 로직 구현.
- **`collectors/writers.py`**: 표준화된 헤더를 적용하여 날짜별로 롤링되는 `resource_YYYYMMDD.csv` 및 `process_YYYYMMDD.csv` 출력 시스템 구축.
- **`collectors/core.py` & `cli.py`**: 기존의 단일 메인 루프를 분리하여, 핵심 로직을 담당하는 `MonitorEngine` 모듈과 터미널 제어를 담당하는 `cli.py` 도구로 TDD 기반 리팩터링을 완료했습니다.

### 2. Streamlit 대시보드 및 데이터 파이프라인 통합
- **`data_loader.py`**: 기존의 `pd.merge_asof` 로직을 완전히 제거했습니다. 대시보드는 이제 컬럼명을 분석해 자동으로 `resource`와 `process` 데이터를 식별하며, 정확히 일치하는 `Timestamp`를 기준으로 병합(`pd.merge`)을 수행합니다.
- **`app.py`**: 새로운 파이썬 수집 메커니즘이 자체적인 수집/집계 주기를 통제하므로, 대시보드에서 수집 주기를 동적으로 설정하던 레거시 UI 컨트롤을 제거했습니다. **날짜 기반 로그 선택 UI로 변경하여, 오늘 기준 최근 1주일 이내 로그를 자동 선택/로드**하도록 사용성을 개선했습니다.
- **`dashboards/*.py`**: 모든 차트가 명시적인 5초 Peak/Avg 파생 컬럼(`CPU_Avg(%)`, `Mem_Usage_Avg(%)` 등)을 바라보도록 맵핑했습니다. `storage.py`는 드라이브명으로 `PhysicalDriveX` 및 `C:` 형식 모두를 인식하도록 정규식을 확장했습니다.

### 3. 실행 래퍼 및 문서 업데이트
- **`start_monitor.bat` & `Monitor.ps1`**: 기존의 Logman 의존성을 제거하고, 단순히 관리자 권한 여부를 체크한 뒤 `.\venv\Scripts\python cli.py start`를 실행하도록 경량화 래퍼로 축소했습니다.
- **문서화(`docs/`)**: `project_structure.md`, `user_manual.md`, `optimization_proposal.md` 파일에 걸쳐 파이썬 수집기에 대한 내용을 업데이트하고, 제거된 기능과 신규 아키텍처의 의도를 명확히 반영했습니다.

## 👨‍💻 주니어 개발자를 위한 딥다이브 가이드 (Deep Dive for Juniors)

이번 업데이트에서 해결된 까다로운 버그 2가지와, 안정성을 극대화하기 위해 도입된 **TDD(Test-Driven Development) 테스트 기법**의 핵심을 상세히 기록합니다. 이 문서를 통해 파이썬 수집기와 대시보드의 연동 원리를 쉽게 파악할 수 있습니다.

### 1. 엑셀 변환 크래시와 "유령 제어 문자(Null Byte)"의 비밀
대시보드에서 엑셀(`openpyxl`)을 다운로드하거나 차트를 열 때 `IllegalCharacterError: DiskTime_:,:,C:,:(%)` 에러가 발생하여 `C:` 드라이브가 누락된 적이 있습니다.
* **원인의 발견**: 파이썬 수집기가 `subprocess` 모듈로 윈도우 파워쉘의 `Get-Partition` 명령어를 호출할 때, 윈도우 인코딩 환경에 따라 눈에 보이지 않는 **특수 제어 문자(`\x00` 등 Null byte)** 나 빈 문자열이 파이프를 타고 들어왔습니다. 이 쓰레기 값들이 걸러지지 않은 채 드라이브 문자로 무분별하게 조합되다 보니 컬럼 이름 텍스트 내부에 지뢰처럼 박혔던 것입니다.
* **아키텍처 레벨의 해결책 (정규화 및 복구)**:
  1. **원천 차단 (`collectors/sampler.py`)**: 이제 파워쉘 출력을 파싱할 때 `str.isalpha()`와 `len() == 1`을 문맥적으로 검사하여 **오로지 A-Z 알파벳 단 한 글자**만 드라이브명으로 엄격하게 인정합니다.
  2. **과거 데이터 자가 치유 (`data_loader.py`)**: 이미 시스템에 오염된 옛날 CSV 파일을 읽을 때 대시보드가 터지지 않도록, 로딩 직후 `re.search(r'_(.*?)([A-Z]:(?:,[A-Z]:)*|PhysicalDrive\d+)(.*?)\(')` 정규식을 돌립니다. 이 강력한 정규식은 오염된 문자열 더미 속에서 `C:` 나 `D:,H:` 같은 진짜 드라이브명만 수술하듯 추출해내어 캐시 메모리에 덮어씁니다. (※ 참고: `(?:,[A-Z]:)*` 패턴은 정규식에서 `D:,E:` 처럼 볼륨이 여러 개 합쳐진 엣지 케이스까지 모두 매칭시키는 문법입니다.)

### 2. 브라우저 없이 GUI를 테스트한다? `verify_dashboards.py` (Mocking 기법)
Streamlit 대시보드 UI를 수정하다 보면 나침반 없이 항해하는 것처럼 버그를 놓치기 쉽습니다. AI 에이전트나 자동화된 CI/CD 파이프라인은 직접 브라우저를 띄워서 스토리지 탭을 매번 눌러볼 수 없기 때문입니다.
* **해결책의 도입**: 이를 극복하기 위해 **헤드리스(Headless) 자가 검증 스크립트**인 `verify_dashboards.py`를 루트 디렉토리에 추가했습니다.
* **작동 원리 (MagicMock)**: Streamlit 라이브러리(`st`)의 그래픽 객체들을 파이썬의 `unittest.mock.MagicMock`이라는 '가짜(Mock) 객체' 인터페이스로 바꿔치기합니다. 
  * 예를 들어 대시보드 코드가 `st.plotly_chart(fig)`를 호출하면, 모니터 화면에 실제로 렌더링하는 대신 가짜 객체가 "아, 방금 `fig` 차트 함수가 에러 없이 호출되었구나!" 하고 메모리에 성공 기록만 남깁니다.
  * 테스트 스크립트는 최신 로그 데이터프레임에서 딱 최상단 1줄(`df.head(1)`)만 잘라내어 빛의 속도로 4개의 대시보드 도메인 함수를 통과시킵니다.
  * 만약 이 과정에서 에러(예: 컬럼 매칭 실패, 자료형 에러)가 단 1개라도 발생하면 스크립트가 붉은색 예외 처리를 반환하며, 무사히 생존하면 `🎉 Self-Test Suite Completed!`를 띄웁니다.
  * **주니어 가이드라인**: 앞으로 대시보드의 데이터 파싱 규칙을 변경하거나 파이썬 수집기를 건드렸다면 **무조건 브라우저 서버를 켜기 전에 이 스크립트 한 줄을 먼저 터미널에 쳐보세요!** 에러를 1초 만에 감지할 수 있습니다. (`.\venv\Scripts\python verify_dashboards.py`)

## 구동 테스트 방법
1. **관리자 권한**으로 실행된 터미널(또는 CMD)을 준비합니다.
2. 백그라운드에서 실행 중이던 파이썬 수집기가 있다면 종료합니다.
3. 수집기 실행: `.\start_monitor.bat` (새로운 관리자 셸 창이 뜨며 `C:\SystemLogs` 폴더에 데이터를 기록하기 시작합니다.)
4. 대시보드 실행: `.\venv\Scripts\python -m streamlit run app.py`
5. 대시보드에서 동일한 타임스탬프로 기록되는 CPU/데이터의 Peak 범위와 Average가 한 줄의 데이터로 안전하게 추적되는 것을 확인합니다.
